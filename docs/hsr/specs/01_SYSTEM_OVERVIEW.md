# ① システム概要

照合日: 2026-10-28。区分は[README](README.md)のA/B/C/Dに従う。

## 完成目標と範囲

[要求] UID検索または手動でキャラクターを選び、育成・装備・最終ステータス・パーティ・敵・補正条件を設定して計算し、そのキャラの通常・強化通常・スキル・必殺・追撃・連携・召喚物/精霊・DoT・撃破等の各攻撃の想定ダメージを一覧比較する。非会心・会心・期待値と、必要なヒット別・成分別内訳を確認できること。単一攻撃内の複数ヒット・追加成分の計算と合算は完成対象に含む。

1ラウンドのオート戦闘、ローテーション、戦闘経過・ターン・SP/EPの自動進行は対象外。既存の `actionSummary` による速度一定の行動値・第1ラウンドの行動回数目安は残っているが、戦闘ダメージの自動合計ではない（[エンジン](../../../games/js/hsrCalcEngine.js)、[画面](../../../games/js/hsrApp.js)の `renderActionValue`）。

## 補正の要求

- 常時効果、入力ステータスの閾値、編成だけで判定可能な効果は自動適用する。
- 使用済みスキル、必殺バフ、敵デバフ、スタック等の任意状況は補正モーダルで指定する。編成だけで未使用スキルをONにしない。
- キャラ・装備・編成から利用可能な候補を抽出し、適切な攻撃・属性・成分だけへ適用する。
- UID/手動の最終ステータスへ含む効果を再加算しない。
- 攻撃の比較表示だけを目的に不要な発動チェックを要求しない。計算値の前提が必要なら状態を選ぶか比較結果として示す。

## 用語・品質

攻撃レコードは結果候補の定義、成分はその攻撃内の計算要素、Modifierは対象と条件を持つ数値効果。独立した後続行動は、同じスキル由来でも同一攻撃の合計とは限らない。最終値は入力契約であり、UIDがあらゆる戦闘バフを取得するという意味ではない。

固定版の原記録と独立期待値に基づくこと、入力不足は関係する結果だけ停止すること、部分結果を完全合計と誤表示しないことを品質条件とする。受入手順は[07](07_TEST_SPEC.md)、現在の認定と件数は[08](08_PROGRESS_ISSUES.md)から参照する。

初稿の「動作済みと報告」「使用版は報告のみ」という扱いは、今回確認したコード・定義・テストへの参照へ訂正した（C）。外部サービスの現在の全応答や、ゲーム全体の厳密な処理順まで検証済みとはしない（D）。
