# 原神の効果説明と計算への反映

表示専用の原文は `games/genshin/data/original/effect-texts-ja.json` に出典とともに保存する。保存rawの日本語文、またはユーザーが外部確認した日本語原文を扱う。原文登録は計算仕様の検証・昇格を意味しない。

共通の `GenshinIdResolver.describeEffect` は `originalText` と `calculationSummary` を分離する。明示された原文だけを「原文」、明示的な部分引用だけを「原文抜粋」とする。原文を登録していない表示用文章は「TETINETによる説明」とし、原文の存在や一致を推定しない。

補正モーダルの「計算への反映」は、共通表示モデルを通じて現在のRequestを既存Runtimeで評価した実補正値・単位・適用状態を示す。開いている攻撃詳細（未選択時は最初の計算可能な攻撃）が表示対象になる。ステータス補正はRuntime trace、攻撃別補正は既存のentry適用処理を参照し、説明文や生係数から適用値を推定しない。参照値・層数・上限・精錬の説明は別の「計算根拠」へ折りたたむ。原文は効果単位で表示し、modifierごとに重複させない。party効果の精錬は提供者の値を使用する。

既存の `sourceText`、`effectDescription`、`labelJa` は原文の証拠にしない。特に `sourceText` は条件・対象推定にも使われるため、表示の都合で原文へ置換しない。表示専用原文はRuntimeの推定・計算に渡さない。

## ヴォジャニーツァのparty入力

party/providerでは元素スキル使用、現在有効な回復回数、命中、反応後の状態、流星嵐の状態、受け手の配置を入力する。C4はHP40%以上のキャラを回復した回数を追加指定する。回復回数だけでC4成立を推定しない。

これらからSong、C1、C2の分岐、C4、A4の対象、14524の蜜酒状態を導出する。凍結／星拡散は自動成立としない。時間進行・期限の自動判定は行わず、現在有効な状態を選ぶ。

既存party condition stateのactionsキーに原因入力を保存する。原因入力があるRequestでは導出条件を再生成し、武器・C4のHP補正を一度適用してからC1／A4／party ATKを評価する。原因入力のない旧Requestは既存の明示条件を維持する。個別modifierの入力UIはこのproviderに限り表示しない。

表示用原文は保存済み完成文を優先し、精錬テンプレートは対応する値を展開する。未展開のテンプレートを表示せず、未知のパラメータキーを詳細表の見出しにしない。生成されたLead Vocal／Chorusラベルは日本語化するが、原文・内部ID・enum・保存値は変更しない。

### 通常操作を優先するprovider UI

主入力は「元素スキル使用後の状態」（未使用／発動直後／1・2・3回目以降の回復後）に統合し、既存のskill／heals保存値へ変換する。新規追加時は未使用。未使用から使用後へ切り替えた場合は、通常の対敵使用として初撃・角笛命中をONにする。以降の例外指定と旧保存値は維持する。

通常表示には凍結／星拡散後5秒以内、計算対象の現在位置、正式名称「流星の嵐」の現在状態だけを追加する。流星の嵐は生成・起爆後の状況で支援対象が変わるため独立指定を残す。命中の例外は詳細設定へ移し、初期値から変更した項目数を見出しに示す。C4のHP条件を満たした回復回数は実計算を左右する主要条件として通常表示する。C4の初期値0回は維持し、対象HPを推定して最大化しない。

HP評価順、条件導出、武器式は変更しない。計算への反映は入力から分離した確認表示とし、個別効果の詳細も折りたたむ。

## 条件と実値の共通表示契約

自動導出する内部状態は入力にしない。自動では決められない主要条件は本文に表示する。例外条件だけを詳細設定へ置き、導出結果は確認表示とする。聖遺物・武器・天賦・partyのタブは手動条件数を示し、初回は条件入力のあるタブを開く。ヴォジャニーツァの装備・聖遺物など、操作状態から導出できない手動条件は効果確認の折りたたみから外す。

実装済みの補正項目は0でも残し、「条件未成立」「今回の攻撃には非適用」「計算結果が0」を区別する。固定加算と割合、反応ダメージ補正と基礎ダメージ補正、独立倍率を混同しない。入力反映済みの値は再加算せずその旨を示す。未対応・入力不足・計算不能は数値0にせず、計算対象外または算出不可と表示する。独立攻撃はダメージ一覧への案内にする。
