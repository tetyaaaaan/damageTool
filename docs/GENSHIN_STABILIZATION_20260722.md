# 原神計算画面 安定化設計

## 目的

レスポンシブ表示、補正条件、UID反映、計算結果を別々の応急処置ではなく、同じデータ契約と検証手順で保守する。

## UI設計

- 原神固有の新規コンポーネントと保守用調整は `games/css/genshin-tool-ui.css` に集約し、既存基礎CSSから段階的に移す。`genshin-visual-repair.css` のような用途・寿命が不明な上書きCSSは作らない。
- PC/スマホでDOMを複製せず、コンテナ幅とメディアクエリで再配置する。
- 補正条件はページ内に全件展開しない。ページには選択数・要入力数の概要を置き、編集は一つのダイアログで行う。
- 補正ダイアログは「反応／武器／聖遺物／天賦・命ノ星座／その他」の情報源別タブとする。
- ダメージ結果は攻撃名、非会心、会心、期待値の列契約を全タブで共有する。スマホでも数値列は右揃え、攻撃名は一行省略し全文をtitleで確認可能にする。
- 検証幅は 360 / 390 / 430 / 768 / 1024 / 1440px、ライト・ダーク両方とする。

## 計算データ契約

- 入力欄の表示用丸め値とは別に、UID由来の小数値を `data-precise-value` で保持し、計算は精密値を優先する。
- UIDの基礎攻撃力は表示ステータスへ重複加算せず、内部値 `genshinBaseAtkInput` として保持する。
- 中間計算では丸めず、画面出力時だけ整数化する。
- 胡桃「蝶導来世」の攻撃力加算はHP上限参照値と、基礎攻撃力400%の小さい方を使う。
- 層数・回数は0を有効な状態として扱い、0層では表示・計算とも0にする。最大20以下は選択式、それを超える連続値は数値入力とする。

## 補正監査

全補正レコードを次の三層で監査する。

1. 構造: ID、カテゴリ、値、対象、入力契約、上限・層数契約。
2. 意味: 発動条件、効果対象、効果量、装備者／チーム対象、同一効果の重複。
3. 実行: 表示中の現在値とエンジンへ渡る値が一致する代表計算。

監査スクリプトは完全一致重複と構造契約違反を機械検出する。意図した代替レコードは
`auditDisposition: supersededByStructuredRecord` を必須とし、無印の重複を許可しない。

## 完了条件

- 全自動テストが成功する。
- 無制御の完全一致重複と構造契約違反が0件である。
- 胡桃の小数保持・400%上限、UID精密値、0層、ステータス変換を数値テストで確認する。
- 各検証幅でページ全体の横スクロール、主要ラベルの見切れ、ダイアログの画面外逸脱がない。
- P2以降の未対応効果は黙って計算せず、監査レポートに理由と件数を残す。
