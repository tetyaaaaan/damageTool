# 開発規則

このファイルは、ダメージ計算ツールを継続して改良するための共通ルールです。

## 命名規則

- HTMLの `id` は既存互換を優先し、計算処理から参照されている名前は不用意に変更しません。
- 新しく追加する `class` は役割が分かる名前にします。例: `result-card`, `input-grid`, `formula-note`
- JavaScriptの変数名は意味が分かる英語にします。例: `baseDamage`, `damageBonusRate`, `enemyDefenseRate`
- CSV由来のDOM IDは、既存ルールに合わせて接頭辞を付けます。
  - キャラ: `cha_`
  - 光円錐: `wea_`
  - 遺物: `arti_`
  - 合計値: `sumStatus_`

## コメント規則

- 処理をそのまま日本語にしただけのコメントは増やしません。
- コメントは「なぜこの処理が必要か」「どのデータ仕様に依存しているか」を説明する場合に書きます。
- 未完成を示す文言は、公開ページや本番コードでは使いません。
  - 避ける例: `まだ作ってません`, `多分`, `精度は悪いです`
  - 使う例: `現在は通常ダメージのみ対応`, `計算対象外の補正があります`

## デザインシステム

### カラー方針

- tetinetの共通UIは、ライト・ダークともにディープティールをブランドカラーとします。テーマ間で色相を変えず、明度と背景の関係で昼夜を表現します。
- ライトモードは、薄い青灰色のページ背景、白いカード、濃い青緑の操作色を基本とします。紫・ピンク・オレンジを連続させたブランドグラデーションは使用しません。
- メイン操作、選択中タブ、フォーカス、見出しアクセントには共通の操作色トークンを使います。画面やゲームごとに主要ボタンの色を変えません。
- オレンジは警告、赤はエラー、緑は成功など、状態を伝える用途に限定します。
- 元素、レアリティ、ゲーム種別など固有の色は情報として残します。ただし、共通ボタンや共通見出しのブランド色には流用しません。
- 白背景で薄い元素アイコンを表示する場合は、選択画面と同じ暗色の円形バックプレートを使用します。

### サーフェスと装飾

- 通常カードは白または共通サーフェス色とし、選択状態以外で全面をブランド色に染めません。
- カードの区切りは薄い青灰色の枠線と余白を優先し、強い影や多色グラデーションへ依存しません。
- 斜線や幾何学模様は必須要素にしません。使う場合も、見出しなど限定した場所の補助装飾に留めます。
- 主要ボタンは単色のディープティール、補助ボタンは白背景とティールの枠線を基本とします。

### CSS実装

- 色は `--teti-brand`、`--teti-interactive`、`--teti-selected-bg`、状態色など、用途を示すトークンから参照します。
- `--teti-primary` などの既存変数は互換用エイリアスとして扱い、新規CSSでは用途別トークンを優先します。
- 16進カラーをコンポーネントへ直接追加する場合は、元素・レアリティ・警告など固有色である理由が分かる状態にします。
- ライトモード変更時は、トップページ、各ゲーム一覧、計算画面、選択モーダル、UID結果・詳細モーダルを実表示で確認します。

## CSV規則

- 文字コードはUTF-8を使用します。
- 1行目は必ずヘッダー行にします。
- 不要な末尾カンマや空ヘッダーは残しません。
- 数値列は単位を入れず、数値だけを記録します。
  - 良い例: `12`
  - 避ける例: `12%`
- 説明文に半角カンマ `,` は使いません。現在の読込処理は簡易CSVパーサーのため、半角カンマが入ると列ずれします。
- 説明文の区切りには読点 `、` または句点 `。` を使います。
- CSVを更新した場合は、画面でキャラ・光円錐・遺物の選択結果が崩れていないか確認します。

## AdSense向け表記方針

- ページタイトルや説明文に「予定」「精度は悪い」など未完成に見える表現を使いません。
- 計算対象外の仕様がある場合は、免責や注意書きとして丁寧に記載します。
- 外部ゲーム名を扱う場合は、非公式ファンツールであることを明記します。
