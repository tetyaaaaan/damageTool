## 読み方と判定

|区分|意味|扱い|
|---|---|---|
|A|正しい要求について、記載した限定範囲の実装をコード・既存テストで確認|範囲と根拠を記載する。全キャラ・全効果の保証へ拡張しない|
|B|正しい要求だが未実装または部分対応|要求を維持し、既存の残作業台帳へ差分を記録|
|C|初稿の説明に誤り・根拠のない断定があった|実在する実装と区別して訂正。訂正記録は各章・下表|
|D|根拠不足で今回確定できない|未確定と明記。推測で仕様や完了認定を作らない|

`[要求]` は達成すべき動作、`[実装確認]` は確認できた現在の動作。実装確認だけではゲーム仕様の正しさの証明にならない。固定版の原レコード、独立期待値、実装、UI統合受入を分けて確認する。

## 正本と更新先

|情報|管理元|更新タイミング|
|---|---|---|
|要求仕様・実装の設計説明|本ディレクトリの01～07|対応する機能・契約を変更するとき|
|登録状態・E0構成確認|[生成完成管理表](../../HSR_CHARACTER_COMPLETION.md)、[生成器](../../../scripts/reportHsrCompletion.cjs)|入力データ・受入根拠を変更した後に再生成。生成文書を直接編集しない|
|攻撃別の限定条件と検証履歴|[攻撃範囲資料](../../HSR_MAIN_ATTACK_SCOPE.md)|受入範囲や根拠の変更時|
|効果受入・未実装課題・未計測工数|[残作業台帳](../../HSR_COMPLETION_WORKLOAD.md)|効果完了または阻害要因が変わったとき|
|実行時の効果・攻撃定義|[マニフェスト](../../../games/hsr/data/calc/data-files.json)から読むJSON、[ローダー](../../../games/js/hsrCalcData.js)|個別効果実装時。説明文を数式として解析しない|
|数値の出典|各定義のprovenanceが指す固定版原レコード・明示した別根拠|値・条件の採用時。生成物やテストを原仕様の出典にしない|

人数・効果件数・残数は本仕様群へ独立転記しない。08は台帳ではなく索引。初稿の概念図や例だけを理由に、新しいスキーマやエンジンを追加しない。

## 更新と検証

[AGENTS.md](../../../AGENTS.md)、[開発規則](../../DEVELOPMENT_RULES.md)を確認し、必要な範囲だけコードと独立テストを読む。原神CurrentCalcは参照専用。変更した要求・式・登録契約・責務と同じ変更単位で該当仕様を更新する。B/Dの進捗は既存台帳が管理元。

文書変更はリンク先・関数名・文書間整合を確認する。製品変更時は[07](07_TEST_SPEC.md)の変更別手順を使い、検証済みの変更だけローカルcommitする。仕様の監査を全効果の再認定や進捗数の増加として数えない。
