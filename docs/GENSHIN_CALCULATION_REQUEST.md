# 原神計算リクエスト境界

## 目的

画面の入力取得とダメージ計算を分離し、同じ入力を再計算・比較できるようにする。DOM は `CalculationRequest` の生成時だけ参照し、計算本体は受け取ったリクエストと計算データだけを使用する。

## 処理の境界

1. `buildCalculationRequestFromForm()` がフォーム、補正条件、選択中の敵から `CalculationRequest` を生成する。
2. `calculateDamageRequest(request, calcData)` がリクエストを複製して計算する。呼び出し元のオブジェクトと DOM は変更しない。
3. `createCalculationSnapshot(request, payload)` が再計算用リクエストと比較用結果を保存可能な形にする。
4. `runGenshinJsonCalc()` は既存 UI との互換用オーケストレーターとして上記を順に呼ぶ。

`buildCharacterCalcContext()` は既存コード向けの互換名であり、新規コードでは使用しない。

## CalculationRequest

- `schemaVersion`: 現在は `1`
- `calculationInput`: UID由来・手入力の双方を正規化した共通 `CalculationInput v2`。互換用の上位character/weapon/talent/statsフィールドもこの値から投影する
- キャラクター、武器、聖遺物、天賦、ステータス
- 反応、補正条件、段階・回数などの UI 状態
- 敵レベル、耐性、プリセット ID と表示名
- `inputProvenance`: ステータス値の由来（UID・手入力・混在）と加算方針

### ステータス入力と二重加算防止

UID反映後の値も手入力値も、画面上のステータス欄は武器・聖遺物・常時天賦などを含む「最終ステータス」として扱う。`inputProvenance.includesPersistentBonuses` は常に `true` とし、`uidHandling: includedInUidStats` の永続補正を計算時に再加算しない。

計算後から加えるのは、発動条件を持つ戦闘中補正、パーティ補正、元素共鳴など `provenance: externalModifier` の効果だけとする。UID値を一部編集した場合は `source: mixed` として各フィールドの由来を残すが、加算方針は変えない。キャラ・武器を手動で変更した場合は、以前のUID由来の基礎ステータスを破棄し、誤った基礎値による割合バフを止める。

敵プリセットは耐性の入力支援であり、計算本体は展開済みのレベル・耐性を参照する。このためプリセットデータが更新されても、保存済みリクエストは同じ値で再計算できる。

## 攻撃キー

結果には `attack-v1:` で始まる `attackKey` を付与する。表示順やダメージ値ではなく、キャラクター、効果元、攻撃エントリ、攻撃モード、反応 ID から構成する。ステータス変更後も同じ攻撃を対応付けられるため、将来のダメージ比較はこのキーで結合する。

同一キーが一度の計算内で重複した場合だけ `duplicate-N` を付け、結果の欠落を防ぐ。

## CalculationSnapshot

- `schemaVersion`, `createdAt`, `dataVersion`
- 再計算可能な `request`
- `attackKey` と丸め前の `nonCrit`, `crit`, `expected`, `total`

画面表示用に丸めた文字列は保存しない。比較時の誤差と UI 文言変更の影響を避けるため、数値は計算結果の精度のまま保持する。

## ダメージ比較

- 直前比較: 現在のタブ内セッションで一つ前に実行した計算を参照する。
- 固定基準比較: 「現在を基準に固定」したスナップショットをブラウザへ保存し、再読み込み後も参照する。
- 結合: 表示順や攻撃名ではなく `attackKey` が一致する結果だけを比較する。
- 表示: PC は差分値と増減率、狭い画面は増減率を優先して表示する。

異なるキャラクターなど、同じ `attackKey` が存在しない結果へ誤った差分を表示しない。固定基準はユーザー操作でのみ更新し、通常の再計算では上書きしない。

## パーティ状態

`CalculationRequest.party` は `schemaVersion: 2`、メイン1枠、サポート3枠を保持する。各メンバーにはキャラクター、レベル、命ノ星座、天賦、武器・武器レベル・精錬、基礎値、必要な効果だけに使う提供者ステータス、戦闘状態、バフ状態を持たせる。

サポート枠のキャラ・武器はメイン入力と同じアイコン選択モーダルを再利用する。メインキャラおよび他のサポート枠との同一キャラ重複、キャラの武器種と一致しない武器は選択段階と正規化段階の両方で拒否する。

パーティ状態はスナップショットへ保存し、サポートメンバーの天賦・命ノ星座から安全に判定できる補正だけをダメージへ反映する。同一キャラクターの重複は正規化時に除外する。

### パーティ補正の対象

- メインへ適用する: チーム全員、出場キャラクター、装備者以外のメンバー、敵に付与するデバフ。
- メインへ適用しない: バフ提供者自身だけを対象とする効果。
- 表示のみにする: 対象が曖昧な効果、必要な提供者ステータスが未入力の効果、層数・ポイント・人数など追加入力が必要な効果。キャラ・武器から決まる基礎HP・基礎攻撃力・基礎防御力はローカル基礎値データから自動解決する。
- 発動条件がある効果は、補正条件ダイアログの「パーティ」タブでユーザーが明示的にONにした場合だけ適用する。

### 重複ルール

- 同一提供者・同一補正元・同一効果ID・同一対象のレコードは一度だけ適用する。
- 異なる提供者による別効果は、ゲームデータ側に重ね掛け不可の明示がない限り個別に適用する。
- 同一キャラクターを複数枠へ置くことはできないため、同一キャラクター由来の二重適用はパーティ正規化でも防ぐ。
- 補正に `stackingGroup` / `stackingRule` がある場合はデータ定義を優先する。`max` は最大値のみ、`refresh` は後の効果のみを採用する。
- 「千年の大楽章」の同種類効果および原文で同名効果の重ね掛け不可が明記された効果は、異なる提供者でも同じ適用対象・補正種別の最大値だけを採用する。

### 元素共鳴

- 編成済み4枠の元素から自動判定し、同じ共鳴は一度だけ候補化する。
- 常時効果は自動適用し、氷共鳴・岩共鳴・草共鳴の追加条件は「パーティ」タブで明示的にONにする。
- 炎・水の割合補正は総攻撃力・総HPではなく基礎値を使う。基礎値を取得できない手入力状態では推測せず表示のみにする。
- 風・雷・交錯の護りなど、現在の単体ダメージ式へ直接影響しない効果は説明のみ表示する。

## 敵プリセット

初期状態は従来互換の「カスタム」（Lv.90、元素耐性 10%、物理耐性 10%）。プリセット選択中はレベルだけ編集可能で、耐性はプリセット値を表示して入力をロックする。カスタムへ戻ると、直前のカスタム耐性を復元する。

プリセット追加は `games/genshin/data/enemies.json` に閉じ、UI と計算式への条件分岐追加を不要にする。

プリセットはカテゴリ、標準元素耐性、物理耐性、元素別例外、短い注意文を持つ。UIではカテゴリごとにまとめる。元素別例外は表示用だけでなく `CalculationRequest.enemy.resistance.base.byElement` へ保存する。

## 手入力時の基礎値

`base-stats.json` は選択可能な全キャラ・武器の基礎値、成長曲線、突破加算を保持する。ランタイムはキャラLvと武器Lvから基礎HP・キャラ基礎攻撃力・武器基礎攻撃力・基礎防御力を小数のまま算出し、表示用の整数丸めとは分離する。

レベルが突破境界と一致して突破段階が明示されていない場合は、そのレベルで選べる最大突破段階を採用する。キャラはLv.100まで、武器はLv.90までを計算対象にする。UID取得時はAPI由来の精密値を優先する。
