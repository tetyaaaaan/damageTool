# HSR structured calculation data

This directory is the production source for reviewed Star Rail calculation modifiers.

- `modifier-contract.schema.json` defines the canonical modifier shape.
- `attack-contract.schema.json` defines the canonical direct-attack shape and its support boundary.
- `modifiers.json` contains reviewed representative modifiers used to establish the runtime contract.
- `modifiers-character-expanded.json` contains individually reviewed character trace and eidolon modifiers. Character expansion is kept separate from the contract fixtures so coverage can grow without turning one JSON file into a monolith.
- `modifiers-light-cones.json` contains refinement-aware light-cone effects. Persistent final-stat bonuses are excluded from calculation to avoid double application; attack-type and activation-dependent effects are registered here.
- `modifiers-relics-ornaments.json` contains set-piece-aware relic and planar-ornament conditions, including stack, stat-threshold, enemy-state, and attack-scope effects.
- Display descriptions remain in `../catalog.json`; descriptions are never parsed at runtime to decide values, targets, conditions, or calculation stages.

Each record declares its source IDs, unit, target, attack scope, activation input, stacking rule, calculation stage, support status, source provenance, and verification date. Records marked `review` or `displayOnly` must not enter damage calculation.

Run validation with:

```powershell
node scripts/validateHsrModifiers.cjs
node scripts/auditHsrCoverage.cjs
node --test tests/hsr/*.test.cjs
```

`coverage-report.json` is generated by the audit script. It lists every unreviewed attack ID and every catalog record that contains a damage-relevant term but has no structured source registration. Detection is an audit aid only and is never used by the browser runtime.
